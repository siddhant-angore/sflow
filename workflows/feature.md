- **Before** "`how` over the affected subsystem.": Read the Operating behaviors section of the **using-agent-skills** skill and hold to it for the whole task. The task must carry testable acceptance criteria and an out-of-scope list; if it does not, run the **Spec** playbook first.
- **In** "`architect` for parallel design exploration.": Each runner reads the **codebase-design** skill with its `DEEPENING.md` and `DESIGN-IT-TWICE.md` (deep modules, the deletion test, one adapter is a hypothetical seam). A change that adds or alters a contract also reads the **api-and-interface-design** skill (Hyrum's Law, the idempotency-key contract). A UI change also reads the **frontend-ui-engineering** skill. Record a new term in `GLOSSARY.md` and a hard-to-reverse choice as an ADR per the **domain-modeling** skill.
- **After** "Write the throughput checkpoint as four todo items.": Slice the work per the **incremental-implementation** skill: thin vertical slices, each ending in a test, a verification, and a commit, with a NOTICED BUT NOT TOUCHING block. When the task is bigger than one slice, write the slice list with the task template in the **planning-and-task-breakdown** skill (acceptance criteria, verification, size; an XL task is split). Name the test seams per the **tdd-vertical-slices** skill and confirm them with the user before any test is written.
- **In** "Delegate code-writing to a subagent": The brief names the seams, points the delegate at the sections The Prove-It Pattern and Discover the Stack First of the **test-driven-development** skill and the Anti-patterns table of `<sflow>/references/testing-patterns.md`, and requires a citation per the **source-driven-development** skill for every framework-specific API, with `UNVERIFIED:` when none exists. A delegate near its context limit writes the handoff contract from the **context-engineering** skill (scope, task status, changed files, verification commands, open questions) and a fresh delegate continues.
- **In** "Verify on the matching surface.": A web surface is driven per the **browser-testing-with-devtools** skill. A failing verification goes through the **debugging-and-error-recovery** skill (stop adding features, preserve evidence, root cause, regression test) before any retry.
- **In** "If the design is contested, `interrogate` before shipping.": Interrogate already runs a fresh-context multi-model panel; add only the brief rule from the **doubt-driven-development** skill: the reviewer receives the artifact and the contract, never the claim, and findings are classified (contract misread, actionable, trade-off, noise). Do not run its cross-model escalation prompts.
- **Before** "`architect` for parallel design exploration.": Before fan-out or a multi-file change, run the usage check in `usage-handoff.md` of the **sflow** skill. If Claude Code or Grok Bot is below about 15% remaining, pause per that file with the handoff note on the issue, and report the reset time in IST instead of starting.
