**You own the design. Plan, review, verify.** Delegate implementation. Stay in the lead.

- **sflow (before):** Read the Operating behaviors section of the **using-agent-skills** skill and hold to it for the whole task. The task must carry testable acceptance criteria and an out-of-scope list; if it does not, run the **Spec** playbook first.
1. `how` over the affected subsystem.
- **sflow (before):** Before fan-out or a multi-file change, run the usage check in `usage-handoff.md` of the **sflow** skill. If Claude Code or Grok Bot is below about 15% remaining, pause per that file with the handoff note on the issue, and report the reset time in IST instead of starting.
2. `architect` for parallel design exploration.
   - **sflow (in):** Each runner reads the **codebase-design** skill with its `DEEPENING.md` and `DESIGN-IT-TWICE.md` (deep modules, the deletion test, one adapter is a hypothetical seam). A change that adds or alters a contract also reads the **api-and-interface-design** skill (Hyrum's Law, the idempotency-key contract). A UI change also reads the **frontend-ui-engineering** skill. Record a new term in `GLOSSARY.md` and a hard-to-reverse choice as an ADR per the **domain-modeling** skill.
3. Write the throughput checkpoint as four todo items. A dimension that genuinely does not apply (single file, no fan-out) keeps its item with `n/a: <reason>` rather than being dropped:
   - **sflow (after):** Slice the work per the **incremental-implementation** skill: thin vertical slices, each ending in a test, a verification, and a commit, with a NOTICED BUT NOT TOUCHING block. When the task is bigger than one slice, write the slice list with the task template in the **planning-and-task-breakdown** skill (acceptance criteria, verification, size; an XL task is split). Name the test seams per the **tdd-vertical-slices** skill and confirm them with the user before any test is written.
   - **Blocking first steps.** Gates run before fan-out.
   - **Independent workstreams.** Disjoint files, services, or layers parallelize. Shared writes serialize.
   - **Shared mutable state.** Default to splitting the target (the **separate-before-serializing-shared-state** principle skill). Serialize only for real invariants.
   - **Smallest safe decomposition.** If one worker is best, name why.
4. Delegate code-writing to a subagent using your configured feature model (default `grok-4.7-xhigh-fast`) with a specific scope (file paths, named data shape and its organizing structure per **principle-model-the-domain**, a state machine over scattered booleans, a table/registry over branching, a typed model over repeated shape assumptions, chosen before the delegate writes logic, and success criteria). Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section. When the implementation admits multiple valid shapes (error handling, abstraction layer, test structure), delegate via the **arena** skill instead so the runners surface the alternatives and the cross-judge guards the pick. Mandatory: no skip-with-reason escape, and Laziness Protocol does not override it (the gain is review separation, not lines saved). A subagent forbidden to spawn satisfies this by owning the diff directly with the same review separation. No "standing by" reply that waits on a nested agent. Comments per **Comments**. Surgical edits, re-ground against the source for upstream-derived files. Port shared-primitive improvements to all consumers and verify each. Commit liberally.
   - **sflow (in):** The brief names the seams, points the delegate at the sections The Prove-It Pattern and Discover the Stack First of the **test-driven-development** skill and the Anti-patterns table of `<sflow>/references/testing-patterns.md`, and requires a citation per the **source-driven-development** skill for every framework-specific API, with `UNVERIFIED:` when none exists. A delegate near its context limit writes the handoff contract from the **context-engineering** skill (scope, task status, changed files, verification commands, open questions) and a fresh delegate continues.
5. Verify on the matching surface. "Inconclusive" or wrong-surface is not a pass. Flag it.
   - **sflow (in):** A web surface is driven per the **browser-testing-with-devtools** skill. A failing verification goes through the **debugging-and-error-recovery** skill (stop adding features, preserve evidence, root cause, regression test) before any retry.
6. Rebase into small, ordered commits. Stack follow-ups.
   Use the **sequence-verifiable-units** principle skill, building, verifying, and committing each small unit before the next.
7. If the design is contested, `interrogate` before shipping.
   - **sflow (in):** Interrogate already runs a fresh-context multi-model panel; add only the brief rule from the **doubt-driven-development** skill: the reviewer receives the artifact and the contract, never the claim, and findings are classified (contract misread, actionable, trade-off, noise). Do not run its cross-model escalation prompts.
8. Run **Opening a PR**.

Code-coupled work (one feature, one migration) goes to a single owner with the checkpoint inline. That owner fans out internally after the blocking phase. Parent-level fan-out is for slices that produce independent artifacts (audits, cross-subsystem investigations, competing experiments). Rewrite the checkpoint at phase boundaries. Spawn a fresh owner rather than chaining interrupts.
