**You own the questions. The human owns the answers.** Keep steps 1 to 5 in one context window.

1. State your one-sentence hypothesis of what the user wants with a confidence number, per the **interview-me** skill. Below about ninety-five percent, interview.
2. Interview per the **grilling** skill through the **grill-with-docs** skill: every askable question of the round, numbered, each with a recommended answer; update `GLOSSARY.md` and write ADRs inline per the **domain-modeling** skill. Stop when you can predict the next three answers. A question a run can settle goes to the **Prototype** playbook or the **prototype** skill (throwaway branch), bridged by the **handoff** skill. A fact goes to the **research** skill. A raw idea first passes the **idea-refine** skill, whose Not Doing list carries forward. A decision that belongs to someone else becomes the **to-questionnaire** skill.
3. If the work exceeds one session or the map is foggy, run the **wayfinder** skill on the project's tracker and return here when the map clears.
4. Write the spec per the **to-spec** skill and publish it to the tracker named in `docs/agents/issue-tracker.md`, or to `.scratch/<slug>/spec.md` when there is none. Its sections also cover the six areas in the **spec-driven-development** skill (commands, testing, structure, style, git workflow, boundaries) and the boundaries are three-tier: Always, Ask first, Never. If the repo has no quality floor, write `CONSTRAINTS.md` per the **constraint-driven-development** skill and add its guard to the project's checks.
5. Break it into tickets per the **to-tickets** skill: tracer-bullet vertical slices, each sized to one fresh context window, with blocking edges, each carrying the task template fields from the **planning-and-task-breakdown** skill (acceptance criteria, verification command, files, size). The user approves the breakdown before anything is published.
6. Each ticket then runs the **Feature**, **Bug fix**, or **Refactoring** playbook in a fresh context window.

**Reply:** the spec, the ticket list with its blocking graph, the glossary and ADR diffs, the questions that stayed open.
